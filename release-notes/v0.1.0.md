첫 릴리스입니다. JDK 27로 올리기 전에 저장소만 보고 걸리는 것을 PR 코멘트로 남기는 GitHub Action이고, 실행 파일은 이 릴리스에 첨부된 `jvm-risk-scanner.jar` 하나입니다(JDK 21 이상).

무엇을 보는가
- JDK 27 기본값 변화(JEP 523 G1 기본화, JEP 534 압축 객체 헤더)가 실제로 건드리는 지점: GC 플래그, `-javaagent`, `sun.misc.Unsafe`, JOL·lincheck, JFR.
- 런타임·프레임워크 라인의 지원 종료. Spring·Tomcat·Redis는 스캔 시점에 endoflife.date를 읽고, JDK는 배포판별로 날짜가 달라 규칙 파일을 유지합니다.
- CVE는 두 단계로 판정합니다. 취약 버전 범위는 OSV.dev에서 스캔 시점에 가져오고, 규칙 파일에 적힌 사용 흔적 문자열이 소스·빌드·설정에 없으면 INFO로 내립니다. 흔적 규칙이 없는 CVE는 제품당 한 줄로 묶어 MEDIUM으로만 냅니다.
- 권고하는 수정 버전은 Maven Central에 존재하는지 확인합니다. OSV가 적은 Tomcat 10.1.58처럼 없는 버전이면 같은 라인의 다음 버전을 "추정"으로 적습니다.

입력과 출력
- `--deps deps.txt`: `gradle dependencies` 또는 `mvn dependency:tree` 출력을 주면 BOM 추정 대신 실제 해석 버전을 쓰고 전이 의존성까지 봅니다. PowerShell이 만든 UTF-16 파일도 읽습니다.
- `--sarif`, `--sarif-out`: GitHub code scanning 형식.
- `--fail-on high`: 그 심각도 이상이 있으면 종료 코드 1. 조회 실패(UNKNOWN)도 실패로 봅니다.
- `.jvmrisk-ignore`: 검토 끝난 항목 억제. 만료일과 사유가 없으면 무효이고 만료되면 다시 나옵니다.
- `--suggest`: OSV에만 있는 항목을 규칙 파일 항목 뼈대로 출력합니다.

조회 실패 시
OSV·endoflife.date·Maven Central 조회가 실패하면 `SCAN-UNKNOWN` 항목을 남깁니다. OSV는 7일 이내의 마지막 성공 조회가 있으면 그것으로 판정하고 리포트 머리에 나이를 적습니다. 네트워크 없이 규칙 스냅샷만 쓰려면 `--offline`입니다.

알려진 한계
- 빌드 파일은 정규식으로 읽습니다. `--deps` 없이는 전이 의존성을 보지 않고, Kotlin DSL의 `extra[...]`나 버전 카탈로그 같은 변형은 놓칠 수 있습니다. 다음 버전에서 CycloneDX SBOM 입력으로 옮길 계획입니다.
- 멀티모듈은 가장 오래된 Boot 버전을 대표로 잡습니다. 배포되지 않는 모듈이 리포트를 오염시킬 수 있습니다.
- 취약점 데이터 소스가 사실상 OSV 하나입니다. Spring이 2026-08-20에 공개한 권고는 9월 중순까지 OSV에 없었고, 규칙 파일이 그 공백을 메웁니다.
- 사용 흔적 문자열은 사람이 권고문을 읽고 정한 것이라 리플렉션이나 프로퍼티로 켜지는 기능은 놓칠 수 있습니다. INFO로 내릴 때 찾은 문자열 목록을 같이 적는 이유입니다.

사용
```yaml
- uses: cloud911948/jvm-risk-scanner@v0.1.0
```
전체 예제와 휴면 저장소 스캔, 캐시 설정은 저장소의 `example/jvm-risk.yml`에 있습니다.
